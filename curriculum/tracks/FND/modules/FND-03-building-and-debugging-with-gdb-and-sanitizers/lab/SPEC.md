**Mechanism, from `CMakeFiles/CMakeConfigureLog.yaml` (build-doc):** the `fsanitizeaddress` check compiles `cc -DFLAG_SUPPORTED_fsanitizeaddress <CMAKE_C_FLAGS and the flags accumulated so far> -fsanitize=address -o CMakeFiles/cmTC_xxxx.dir/src.c.o -c .../src.c`, then links `cc <same flags WITHOUT -fsanitize=address> -rdynamic src.c.o -o cmTC_xxxx` and fails with `undefined reference to '__asan_init'` and `'__asan_version_mismatch_check_v8'`. So the check's flag is passed at compile time only; the CMake docs' silence is answered by the log. Loop at CMakeLists.txt lines 98-106, list at 64-76 (87d8f096).

**Item 2, "18 tests":** NOT reproduced. With explicit sanitizer flags, `-O0` and `-O2`, with and without `-DENABLE_CUSTOM_COMPILER_FLAGS=OFF`, Debug and Release, `ctest -N` lists 19 tests every time (identical list): the 18 unity tests (parse_examples parse_number parse_hex4 parse_string parse_array parse_object parse_value print_string print_number print_array print_object print_value misc_tests parse_with_opts compare_tests cjson_add readme_examples minify_tests) plus `cJSON_test` (from test.c, top-level CMakeLists.txt lines 245-267). With `-DENABLE_CJSON_UTILS=ON` it is 22. The builder's 18 is probably the 18 unity tests (e.g. a build target list), or a run that omitted `cJSON_test`; the 19th is `cJSON_test`. The lab's `-O2` build reports 19/19.

**Item 3, Drill 2 determinability (verified by the image build against the real binaries):** asan_code: `nm -D mN | grep -c __asan_report` (works on stripped m6: dynamic imports); asan_runtime: `ldd`; ubsan: `nm -D ... __ubsan_handle`; opt: for the stripped m6 `nm` says "no symbols", but `readelf -h` gives the entry point, `objdump -d` at that address shows `lea ...(%rip),%rdi` before `call *...@GOTPCREL` (main's address passed to `__libc_start_main`); `main` at O0 starts `push %rbp; mov %rsp,%rbp; sub ...; mov %edi,-0x14(%rbp)` (argument spills), at O2 `push %r13; push %r12; push %rbp; push %rbx; mov %edi,%ebx` with no frame pointer setup and register-only code. Determinable, but it needs this multi-step recipe. **TRAP for debug_info:** m4 (`-O0 -fsanitize=address`, no `-g`) has `.debug_info`, `.debug_line` etc. because libasan's statically linked `asan_preinit` object carries DWARF (`DW_AT_producer ... -g -O2 ... asan_preinit.cpp`); `file m4` even says "with debug_info". So `readelf -S | grep debug` or `file` give a wrong `debug_info=yes`; correct evidence is whether the program's own CU is present (`readelf --debug-dump=info m4 | grep DW_AT_name` shows only libsanitizer names; `gdb -batch -ex 'info line main' m4` says "No line number information available"). The source needed changes so instrumentation survives -O2: the first draft (memset then fixed-index store, constant-ish add) lost every `__asan_report` and `__ubsan_handle` call at -O2; the final source indexes `p[argc]` and returns `v == 0`.

# Rubric: FND-03-building-and-debugging-with-gdb-and-sanitizers

Automated checks (`lab/check.sh`, host side; exit 0 = outcome pass; see `lab/SPEC.md` for exactly what each mode asserts):
- `check.sh challenge`: the struggle-challenge build and `answers.md`. Mounts the learner's files read-only. Runs the registered test executables directly (not `ctest`). Expected answers are derived live with `gdb -batch` on the learner's own `parse_examples`; there is no stored key. A correct build prints 10 PASS lines and exits 0. The UBSan-fatal check rebuilds `ubtrip.c` with the flags the build actually used, taken from `compile_commands.json`. An `ENABLE_SANITIZERS=ON` build fails on instrumentation only (first offender `cJSON_test`); it **is** UBSan-fatal, because the option's `-fno-sanitize-recover` survives its check (`FLAG_SUPPORTED_fnosanitizerecover=1`, below). `FAIL  instrumentation: first offender is cJSON_test`
- `check.sh project`: runs `build-asan.sh [SRC] [WORKDIR]` twice from `/src/cjson`, re-verifies each `BUILD_DIR=` (last output line) independently of the script's own output, including that UBSan is fatal with the flags that build used (from `compile_commands.json`). It then runs the script on a mutated source copy whose `CMakeLists.txt` adds `add_compile_options(-fno-sanitize=address)` (objects lose instrumentation, the link keeps `libasan`). The script must build under `WORKDIR` and keep the build tree, and it must then reject the build: the checker confirms the built test programs exist under `WORKDIR` and requires a non-zero exit. If the mutant's build still has real ASan instrumentation (for example via a compiler wrapper), accepting it is not failed; the checker reads the mutant's actual `__asan_report` count first. Also checks that `/src/cjson` is unchanged. `FAIL  verify stage: script exited N on the mutated tree, but no parse_examples was left under WORKDIR. Build under WORKDIR and keep the build tree when verification fails (a refusal before the build does not count)` `FAIL  ubsan fatal: UBSan findings would not fail a test (tripwire exit status 0 or no report)` (printed once per run)
- `check.sh --health`: the lab's self-test (about 100 to 115 s measured with 14 fixtures). Run it first when a checker result looks wrong.
- `/opt/osvr/fnd03/tools/mystery-check` (inside the image): Drill 2, salted hashes, prints `match`/`differ` per field only. It includes the `debug_info` trap (a no-`-g` ASan binary that still carries libasan's DWARF).

Feedback type: the checkers give **outcome** feedback. The assessor gives **informational** feedback (which criterion failed and where) first, and **corrective** feedback (the specific change) only after the learner has attempted a revision.

Reference facts for the assessor (derived by the module-builder and measured by the lab-engineer in `osvr-fnd03:1`, 2026-11-11, gcc 14.2.0-19, cmake 3.31.6; `lab/SPEC.md` Implementation notes win if they differ):
- With `-DENABLE_SANITIZERS=ON` and no sanitizer flags of one's own: `ctest` 19/19 pass; `tests/parse_examples` has 0 `__asan_report` and 11 `__ubsan_handle` symbols; only `libubsan.so.1` linked. `CMakeCache.txt`: `FLAG_SUPPORTED_fsanitizeaddress`, `FLAG_SUPPORTED_01`, `FLAG_SUPPORTED_fsanitizeinteger` empty; `fsanitizeundefined`, `fsanitizefloatcastoverflow`, `fsanitizeaddressuseafterscope`, `fnosanitizerecover` = 1.
- Cause: `CMakeLists.txt` lines 98 to 106 run `CHECK_C_COMPILER_FLAG` per flag (list at 64 to 76). In `CMakeConfigureLog.yaml` the `fsanitizeaddress` check compiles `cc -DFLAG_SUPPORTED_fsanitizeaddress <flags> -fsanitize=address -o CMakeFiles/cmTC_xxxx.dir/src.c.o -c .../src.c`, then links `cc <same flags without -fsanitize=address> -rdynamic ...src.c.o -o cmTC_xxxx`, failing with `undefined reference to '__asan_init'` and `'__asan_version_mismatch_check_v8'`. A strong-pass `rootcause.md` quotes both the compile and the link line. `-01` (digit zero) is not a valid option; `-fsanitize=integer` is Clang-only. Verdicts: address check wrong, the other two correct.
- History: `-01` added in `a09defec4c093103cd33a7b70bc43449a3f9171d` (2017-02-07, with `ENABLE_SANITIZERS`), removed in `a20be7996dbb05631fbc98ab48fa6be31fe5c275` (2024-05-09); visible from the pinned checkout only with `git log --all`. Later tags change `CMakeLists.txt` only by dropping `-01`; `cmake_minimum_required` is 3.0 in v1.7.18 and v1.7.19 and 3.5 at the newest commit (changed by `a29814f`, 2026-02-07).
- Later versions are affected, measured: v1.7.18 (`acc76239bee01d8e9c858ae2cab296704e52d916`), v1.7.19 (`c859b25da02955fef659d658b8f324b5cde87be3`) and the newest commit `6d9f2443ab071f86e5d9b43025a40929ec41c46c` (2026-09-16) all give `ctest` 19/19, `tests/parse_examples` with 0 `__asan_report` and 11 `__ubsan_handle`, `libubsan` only; `FLAG_SUPPORTED_fsanitizeaddress` and `FLAG_SUPPORTED_fsanitizeinteger` empty (no `FLAG_SUPPORTED_01` entry).
- With explicit `CMAKE_C_FLAGS="-g -O0 -fno-omit-frame-pointer -fsanitize=address,undefined -fno-sanitize-recover=undefined"`: 19/19 pass, `tests/parse_examples` has 9 `__asan_report` symbols, 10 `__ubsan_handle`, `libasan.so.8` and `libubsan.so.1` linked; `cJSON.c.o` for the library has 8; `compile_commands.json` has 23 entries. 19 registered tests (18 Unity tests plus `cJSON_test`); 22 with `-DENABLE_CJSON_UTILS=ON`.
- Stripped test binary: `nm` says `no symbols`, `nm -D` still counts 9 and 10. A verify stage that uses plain `nm` on stripped artefacts would fail; on the unstripped build both work.
- Q3 reference: at `break __asan_report_store1` on the tripwire, `addr` = `0x502000000018`, shadow `0xa047fff8003`, `x/1xb` = `0xfa` (legend: "Heap left redzone"; here the redzone after the 8-byte block). The report's shadow rows are application addresses, so the learner must compute the shadow address.
- `lab/src/ubtrip.c` (`int x = INT_MAX; x += argc; return x == 12345;`) exits 0 with recoverable UBSan and 1 with `-fno-sanitize-recover`.
- Tests include `../cJSON.c` via `tests/common.h` line 26, so each test executable carries its own instrumented copy of the library.
- Challenge answers: `file_test3_should_be_parsed_and_printed`, `inputs/test3`, `width`, `500`.

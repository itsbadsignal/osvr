## Checker idea
`check.sh [repro|hardening|realbug]` (default `repro`; an unknown mode prints `usage: check.sh [repro|hardening|realbug]` and exits 2). `NO_CACHE=1 ./build.sh` rebuilds the fnd02 and iperf images without cache; the shared base is rebuilt only with `BASE=1`. Host side, `PASS`/`FAIL` per line with a one-line informational reason. It must not explain the bug or suggest code. Exit 0 only if all pass. Target under 30 s.

`repro`, against `~/osvr-work/fnd02/project/repro/repro.c` (override with `REPRO=`):
1. The file exists, is under 60 lines, and includes no OpenSSL header.
2. It compiles in the image with the asan flags plus `-Wall -Wextra`. Report warnings but do not fail on them.
3. The vulnerable run's stderr contains `ERROR: AddressSanitizer: heap-buffer-overflow`, `WRITE of size 1`, and `is located 0 bytes after N-byte region` for some N >= 2. Print N.
4. The **access** frame `#0` function differs from the **allocation** stack's first non-allocator frame function (skip `malloc`/`calloc`/`realloc`/interceptor frames). This enforces the iperf shape: allocate in one function, terminate in another. FAIL message: "allocation and overflowing write are in the same function".
5. With `-DFIXED`: exit 0 and no `AddressSanitizer` in stderr.
6. `predicted.txt` exists and is non-empty, and contains no hex address that also appears in the run's output. That is a crude check that it was not pasted from the run. Note: this is a heuristic, say so in the output.
7. Run `ASAN_OPTIONS=detect_leaks=0` if LSan misbehaves in the container (see FND-01 lab notes). Leaks are not the subject.

`hardening`: build `repro.c` default and weak (without sanitizers), print the four properties per build with the `readelf` line that proves each, then run both and print exit status and stdout. No PASS/FAIL. This is the reference the assessor compares `hardening.md` against.

`realbug` (revised 2026-11-11, audit round 1; measured by the lab-engineer), against `$WORK/realbug/harness.c` (`WORK` defaults to `~/osvr-work/fnd02`), read-only, under `--network=none`, inside `osvr-fnd02-iperf:1`. It builds with `gcc -g -O1 -fsanitize=address -fno-omit-frame-pointer -I<tree> harness.c <tree>/iperf_auth.o -lssl -lcrypto` against `/src/iperf-vuln/src` (4eab661d) and `/src/iperf-fixed/src` (4e5313ba) and runs each with `ASAN_OPTIONS=detect_leaks=0:fast_unwind_on_malloc=0`. PASS lines: `heap-buffer-overflow`; `WRITE of size 1`; `access at decode_auth_setting iperf_auth.c:390`; `fixed 4e5313ba: no AddressSanitizer report (exit status 0)`. The allocation site (`decrypt_rsa_message` :311) is printed on an INFO line. It does not read learner-saved output files. Learner helper: `/opt/osvr/fnd02/tools/realbug.py vuln|fixed harness.c` (same build line and environment, prints to the terminal).

`predict-check PRED_FILE -- CMD...` (inside the image): runs `CMD`, parses the first ASan report and prints, per field, the predicted value, the actual value and `match`/`differ`. Fields: `kind`, `op` (READ/WRITE), `size`, `offset` (bytes after/before/inside), `region` (bytes), `frame0` (function:line; **frame0 is the first frame that is not a sanitizer interceptor or libc frame**, i.e. the first frame in the program's own source), `alloc` (function:line). Global-variable reports: `region` is the variable's size and `alloc` is the variable name. Prediction file format, one `key: value` per line, unknown keys ignored, missing keys reported as `not predicted`. For stack reports, `region` is the frame object's `[a, b)` size and `alloc` is the frame-object's variable name. Also print any UBSan `runtime error:` line verbatim. Exit status: 0 = a report was found, 1 = no report, 2 = usage error. Python 3 stdlib only. Include two fixtures: `upper.c` with a correct prediction and with one wrong field.

**glibc at free (variation 2; non-ASan, default and weak builds identical).** Harness: allocate `KEYSIZE`, allocate a neighbour of the same size, write `p[KEYSIZE]=0`, free both; and a 10-pair variant that fills the tcache. KEYSIZE 8, 25, 128, 256, 384, 512: silent. KEYSIZE 24 and 40 (usable == KEYSIZE, the NUL hits the next chunk's size field): `free(): invalid pointer` (1 pair; the neighbour's size became 0) and `free(): invalid next size (fast)` (10 pairs). KEYSIZE 264 (usable == 264): silent with 1 pair, `double free or corruption (!prev)` with 10 pairs. So what happens depends on whether the byte is slack (silent) or metadata, and on whether the damaged chunk is later freed through a path that checks it.

**frame0 rule (asanparse docstring, `predict-check --help`).** frame0 = the first frame of the access stack that is not a sanitizer interceptor or libc frame, i.e. the first frame in the program's own source. Skipped: function names starting `__asan`, `__interceptor`, `__sanitizer`, `__ubsan`, `__libc_`; source paths containing `libsanitizer`, `sanitizer_common`, `/asan/`, `../csu|sysdeps|string|libio|stdlib|malloc/`, `/glibc`; frames with no source location (libc.so.6). Fallback if none qualifies: first frame. Effect: the memset fixture (`memsetov.c`) reports `#0 memset ...sanitizer_common_interceptors_memintrinsics.inc:87`, frame0 = `clear:7`. The wrong-fix `upper.c` (`i < n`) reports frames through `printf_common`/`vsnprintf`/`snprintf` and frame0 = `main:31`. Global reports: `is located N bytes after global variable 'NAME' defined in 'FILE:L:C' (0x..) of size S` gives offset N, region S, alloc NAME. Allocation skipping also skips `CRYPTO_malloc|CRYPTO_zalloc|CRYPTO_realloc`.

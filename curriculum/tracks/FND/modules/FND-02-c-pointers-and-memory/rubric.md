Reference facts for the assessor (verified by the lab-engineer and the auditor in the image's `/src/iperf` clone, `lab/SPEC.md` Implementation notes). At `4eab661d`, `src/iperf_auth.c`:
- allocation: `*plaintext = (unsigned char*)OPENSSL_malloc(keysize);` in `decrypt_rsa_message`, line 311;
- `plaintext_len = keysize;` line 321;
- write: `plaintext[plaintext_len] = '\0';` in `decode_auth_setting`, line 390;
- a learner who cites tag `3.19.1` instead should give lines 313 (`keysize + 1`), 324 and 395. That is acceptable only if they say it is the fixed release;
- in the OpenSSL 3 branch, `plaintext_len = keysize;` is assigned before `EVP_PKEY_decrypt`, and that call's return value is not checked;
- the fix changes the allocation to `keysize + 1`. Other hunks: error-return checks (`ret =`), `< 0` to `<= 0`, and `OPENSSL_free(plaintext)` on early returns (leak hygiene);
- versions: "fixed in 3.19.1" rests on the MITRE record's "before 3.19.1" plus git evidence (cherry-pick `42280d2292ed5f213bfcb33b2206ebcdb151ae66` in tag 3.19.1, patch-id identical to `4e5313ba`). The GitHub advisory lists patched versions as "Unknown". A learner who writes "not fixed in 3.19.1" because `git tag --contains` omits it has fallen for the cherry-pick false negative;
- the lab's `check.sh hardening` facts for any `repro.c` on this image: **no canary in either build** (the lab gcc does not enable the stack protector by default); PIE and `GNU_RELRO` (partial RELRO, no `BIND_NOW`) in the default build only; NX in both. Without ASan both builds normally run silently for typical key sizes (slack; README Theory).
